# 🎟 VoucherShop — автовыдача ваучеров через DesslyHub

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayCardinal) **v0.1.17+**

**Автор:** yungspider

Покупатель оплатил лот с ваучером / подарочной картой (Steam, Google Play, игры) — плагин сам
покупает ваучер через API [DesslyHub](https://desslyhub.com/ru) и мгновенно отправляет
покупателю серийный номер и PIN-код. В legacy API коды приходят сразу в ответе на покупку;
в API v2 — в результате заказа (плагин следит за статусом).

## Как это работает

```
новый заказ FunPay
      ↓
привязка лота: «Google Play 500₽» → root_id 1024 + variant_id 6278 (+ количество для v2)
      ↓
проверки: баланс DesslyHub, остаток у поставщика (stock), лимит стоимости, маржа, ЧС
      ↓
покупка: voucher {root_id, variant_id, quantity}  → transaction_uuid / order_id
      ↓
legacy: коды сразу в ответе · v2: опрос заказа → service_result.vouchers
      ↓
покупателю: серийный номер + PIN (+ срок действия) · error → алерт продавцу
```

## Возможности

- 🎟 **Полный цикл по API DesslyHub**: каталог ваучеров (цена, валюта, остаток) → покупка
  (`voucher`) → выдача кодов покупателю → для v2 опрос статуса заказа до финала.
- 🌐 **Два поколения API**: legacy (заголовок `apikey`, коды сразу в ответе, покупка
  по одному ваучеру) и v2 (HMAC-подпись `key+secret`, единый эндпоинт `/orders`,
  поддержка `quantity`) — определяется автоматически.
- 🔎 **Встроенный поиск по каталогу ваучеров в меню**: цены, валюта, остаток (stock),
  готовые строки привязок.
- 🔗 **Привязка лотов через меню**: `Название лота | root_id | variant_id [| количество]`.
- 📦 **Контроль остатков**: если у поставщика `stock = 0` — заказ не выполняется (деньги не
  тратятся), продавец получает уведомление, покупатель — извинение (если задан текст ошибки).
- 🧪 **DRY-RUN по умолчанию** — весь сценарий проходит, но покупка **не совершается**.
- 🛡 **Защита денег**: порог баланса, лимит стоимости, минимальная маржа (цена ваучера в USD
  против цены лота FunPay), **ровно одна покупка на заказ**.
- ⚠️ **Понятные ошибки по-русски**: `-300` ваучер не найден, `-301` нет в наличии,
  `-2` недостаточно средств и т.д.
- 🔁 **Сетевые сбои ретраятся**, бизнес-ошибки — нет (деньги не тратятся дважды).
- 💾 Состояние на диске: перезапуск Кардинала не теряет заказы; оборванная покупка
  **не повторяется автоматически** (заказ передается вам).
- 📋 Меню `/voucher`: баланс, каталог, привязки, история, лимиты, тексты сообщений.

## Установка

```bash
cd /home/fpc/FunPayCardinal
wget https://raw.githubusercontent.com/yungspiderq/FPC-VoucherShop/main/voucher_shop.py -O plugins/voucher_shop.py
sudo systemctl restart FunPayCardinal@fpc
```

или отправьте файл боту в Telegram → `🔌 Плагины` → `➕ Добавить плагин`.

> ⚠️ Лоты с ваучерами **не должны** быть в `configs/auto_delivery.cfg` — иначе Кардинал
> выдаст товар сам (и вы заплатите дважды).

## Первый запуск (по шагам)

1. `/voucher` → **🔑 API-ключ** (и **🔐 Секрет**, если у вас ключ v2) — выдаёт менеджер
   DesslyHub ([@DesslyHub_Manager](https://t.me/DesslyHub_Manager)).
2. **🧪 Тест подключения** — покажет поколение API, баланс и курс RUB.
3. **🎟 Каталог ваучеров → 🔎 Поиск** — введите часть названия (например `7 Days`),
   посмотрите цену, валюту и остаток, скопируйте строку привязки (`root_id | variant_id`).
4. **📦 Привязки лотов → ➕ Добавить**:
   ```
   7 Days to Die Steam Key | 1024 | 6278
   Google Play 500₽ x2 | 2048 | 7001 | 2
   ```
   Количество (4-е поле) работает только в API v2; legacy покупает по одному ваучеру.
5. Сделайте **тестовый заказ**, оставив **DRY-RUN включенным**: придет карточка
   «что было бы куплено» — ваучер, цена, количество.
6. Проверьте карточку и только затем **выключайте DRY-RUN** и включайте плагин.

## Использование

Команда **`/voucher`** (или `⚙️ Настройки` на странице плагина):

| Кнопка | Действие |
|---|---|
| 🔴 Включить / 🟢 Выключить | Master-switch автовыдачи |
| 🧪 DRY-RUN: ВКЛ/ВЫКЛ | Тестовый режим: всё считается, но покупка не совершается |
| 🔑 API-ключ / 🔐 Секрет (v2) | Ввести ключ и секрет DesslyHub (в меню маскируются) |
| 💳 Баланс | Всего / доступно / резерв / овердрафт мерчанта DesslyHub |
| 🧪 Тест подключения | Поколение API + баланс + курс RUB |
| 🎟 Каталог ваучеров | Поиск, цены, валюта, остаток, строки привязок |
| 📦 Привязки лотов | Список, ➕ добавление, 🗑 удаление |
| 🧾 История операций | Последние заказы: статус, ваучер, цена, коды, текст ошибки |
| 🔄 Проверить транзакции | Немедленно опросить статусы всех активных заказов (v2) |
| 🛡 Лимиты и защита | Лимит покупки, порог баланса, маржа, валюта FunPay |
| 💬 Тексты сообщений | Текст выдачи кодов, текст при ошибке |
| 🌐 API: auto/legacy/v2 | Переключение поколения API |

### Тексты по умолчанию

Выдача кодов:

```
🎟 Ваш ваучер: $voucher_name

$vouchers

Активируйте его до истечения срока действия (если указан). Если возникнут
сложности - напишите, я на связи.
Спасибо за покупку, $username! Будем рады вашему отзыву ⭐
```

`$vouchers` — список купленных кодов в формате `Серийный номер: … · PIN: … · Действует до: …`
(по одному на строку). Также работают переменные Кардинала (`$username`, `$order_desc`, …),
`$order` (номер заказа) и `$voucher_name` (название ваучера). При ошибке покупателю по
умолчанию **ничего не отправляется** (`failed_text` пустой) — например, можно задать
извинение на случай «ваучер закончился у поставщика».

## Настройки

`storage/plugins/voucher_shop/settings.json` — можно править руками (перечитывается при каждом
обращении) или через меню `/voucher`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | master-switch: обрабатывать ли заказы |
| `dry_run` | `true` | тестовый режим — покупка не совершается |
| `apikey` / `secret` | `""` | ключ DesslyHub и секрет для API v2 (HMAC) |
| `api_mode` | `auto` | `auto` / `legacy` / `v2` — поколение API |
| `base_url` | `https://desslyhub.com` | адрес API |
| `timeout` / `retries` | `20` / `2` | таймаут запроса и число повторов при сетевом сбое |
| `ask_for_data` | `true` | (не используется — данные покупателя не нужны) |
| `success_text` | см. выше | сообщение покупателю с кодами |
| `failed_text` | `""` | сообщение покупателю при ошибке (пусто = не отправлять) |
| `poll_interval` | `10` | интервал опроса статусов заказов (v2), секунд |
| `poll_max_minutes` | `90` | после этого заказ считается «зависшим» → алерт |
| `min_balance_usd` | `5` | порог баланса DesslyHub (ниже — не покупаем + алерт) |
| `max_order_cost_usd` | `100` | лимит стоимости одной покупки |
| `min_margin_percent` | `0` | минимальная маржа, `0` = проверка выключена |
| `funpay_currency_code` | `5` | код валюты цены заказа (5 RUB, 1 USD, 3 EUR, 18 UAH, 37 KZT) |
| `notify_low_balance` | `true` | уведомление в Telegram о низком балансе |
| `low_balance_repeat_minutes` | `60` | пауза между повторными алертами, минут |
| `mappings` | `{}` | привязки лотов: `{ "название лота": {"root_id":…, "variant_id":…, "quantity":1} }` |
| `catalog_cache_minutes` | `720` | время жизни кэша каталога |

Данные: `storage/plugins/voucher_shop/orders.json` (журнал заказов и транзакций),
`storage/plugins/voucher_shop/catalog.json` (кэш каталога).

## Важно знать

- **Деньги.** Покупка совершается только при выключенном `dry_run` и только после всех
  проверок. На один заказ — ровно одна покупка: повторные события FunPay и перезапуск
  Кардинала не приводят ко второму списанию.
- **Перезапуск во время покупки.** Заказ помечается `error` и приходит алерт — автоматически
  повторять нельзя (неизвестно, успел ли запрос дойти). Проверьте операции DesslyHub;
  если ваучер купился — коды можно взять там и выдать вручную.
- **Остатки.** Перед покупкой плагин проверяет `stock` в каталоге. `stock = 0` → заказ
  помечается `failed` (`-301` нет в наличии), деньги не тратятся, вам приходит уведомление.
  Каталог кэшируется `catalog_cache_minutes` — реальная покупка всё равно упрется в ошибку
  поставщика, если ваучер закончился между обновлением кэша и заказом.
- **Количество.** `quantity > 1` поддерживается только API v2. В legacy привязка с
  количеством отклоняется с понятной ошибкой — сделайте отдельные лоты или перейдите на v2.
- **Срок действия.** Если у ваучера есть `expiration`, он выводится вместе с кодами —
  покупатель видит, до когда активировать.
- **API-ключ** хранится только на вашем сервере в `settings.json`, в меню показывается
  маскированным, в логи не пишется и никуда не передается, кроме `desslyhub.com`.

## Используемые методы API DesslyHub

| Поколение | Метод | Зачем |
|---|---|---|
| v2 | `GET /api/v1/catalog/vouchers` | каталог ваучеров (поиск в меню) |
| v2 | `GET /api/v1/catalog/vouchers/{id}` | варианты: цена, валюта, остаток |
| v2 | `POST /api/v1/orders` (`service_type: voucher`) | покупка (`reference` = номер заказа) |
| v2 | `GET /api/v1/orders/{order_id}` | опрос статуса; коды в `service_result.vouchers` |
| v2 | `GET /api/v1/balance` | баланс мерчанта |
| v2 | `GET /api/v1/currency/exchange_rates/steam/{code}` | курс для маржи |
| legacy | `GET /service/voucher/products` | каталог ваучеров и вариантов |
| legacy | `POST /service/voucher/buy` | покупка (1 ваучер); коды сразу в ответе |
| legacy | `GET /merchants/transaction/{id}/status` | опрос статуса (если коды не пришли сразу) |
| legacy | `GET /merchants/balance` | баланс мерчанта |
| legacy | `GET /exchange_rate/steam/{code}` | курс для маржи |

Документация: [desslyhub.readme.io](https://desslyhub.readme.io/reference/introduction),
коды ошибок: [error-codes](https://desslyhub.readme.io/reference/error-codes).

## Состав репозитория

- `voucher_shop.py` — плагин (класть в `plugins/`).
- `tests_plugin_voucher_shop.py` — тесты (**97 проверок** на моках: метаданные, настройки,
  авторизация legacy+v2 (HMAC), автоопределение API, ретраи, хранилище, весь Telegram-UI,
  привязки с количеством, выдача кодов legacy (SN+PIN сразу) и v2 (через опрос заказа),
  прибыль в истории, `stock = 0` → `-301`, ваучер не найден → `-300`, отказ legacy при
  `quantity > 1`, DRY-RUN, маржа, идемпотентность, восстановление после перезапуска,
  поллер и таймауты, каталог в меню, удаление плагина). Запуск из корня FunPayCardinal:
  ```bash
  cp tests_plugin_voucher_shop.py /path/to/FunPayCardinal/
  cd /path/to/FunPayCardinal && pip install -r requirements.txt && python3 tests_plugin_voucher_shop.py
  ```
  Тесты создают настройки во временной папке — ваши реальные `storage/plugins/voucher_shop/`
  не затрагиваются, запросов в интернет нет.
